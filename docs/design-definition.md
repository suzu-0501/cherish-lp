## 0. 前提・矛盾・未確定事項

### 0.1 要件定義書との調整点

要件定義書の中心メッセージ候補「40代から、後ろ姿は変えられる。」は、同書の「結果を保証しない」という表現方針と緊張関係がある。デザイン上は以下のように扱う。

- Hero推奨案：**「肩甲骨から、後ろ姿をもっと好きに。」**
- 補助コピー：**「40代からの肩甲骨はがし・背中美容」**
- 「40代から、後ろ姿は変えられる。」は、オーナー確認および広告表現確認前の代替案としてのみ保持する。

### 0.2 未提供・未確定

- 正式なロゴデータは未提供。サンプルではテキストロックアップを使用し、ロゴを捏造しない。
- 公式ブランドカラーの明文化資料は未提供。本書の色はInstagramの既存投稿から導いた**提案用カラーパレット**であり、公式色とは断定しない。
- 添付素材はスクリーンショットであり、実装用の高解像度写真ではない。最終実装には元画像が必要。
- 店舗情報、予約URL、料金、営業時間、掲載許諾は要件定義書どおり公開前確認とする。
- 顧客の顔が写る写真・ツーショットは使用しない。顔の写らない背面Before/Afterと、匿名の手書きコメントのみ掲載候補とする。

### 0.3 デジタル庁デザインシステムから参照する範囲

参照するのは、情報階層、読みやすい文字設計、レスポンシブ、状態設計、コントラスト、フォーカス、操作領域、セマンティクス等の品質基準である。色、書体、角形状、Hero、カード、写真、余白の演出は流用しない。

品質基準として、本文は原則16px以上、本文行高は1.5以上、長文幅は全角40字程度を上限目安とし、テキストは背景に対して4.5:1以上、操作対象は44×44px以上を採用する。見出し階層は飛ばさず、FAQ以外の重要情報をアコーディオン内へ隠さない。

# 1. デザインコンセプト

## 1.1 ビジュアルコンセプト

**Quiet Confidence — 静かな自信をつくる、背中のためのプライベートケア。**

柔らかな美容感だけでなく、「身体を見てもらえる安心」「大人の女性が落ち着いて相談できる信頼」「自分の後ろ姿と前向きに向き合える気持ち」を同時に表現する。

Instagramに見られるアイボリー、ベージュ、くすみローズ、丸いトリミング、柔らかな自然光をブランドの手掛かりとして残す。一方で、LPでは文字の可読性、写真の大きさ、構図の余白、深いボルドーのコントラストを加え、個人投稿から一段上のブランド体験へ引き上げる。

## 1.2 与えたい印象

優先順は以下。

1. 安心して相談できる
2. 清潔で信頼できる
3. 大人っぽく上質
4. やさしく親しみがある
5. 後ろ姿に前向きになれる

「高級すぎて敷居が高い」「若い人向け」「医療機関のように冷たい」「強く売り込まれる」と感じさせない。

## 1.3 デザインキーワード

- Quiet luxury
- Warm expertise
- Back beauty
- Private care
- Soft editorial
- Natural light
- Personal expertise

## 1.4 店舗らしさの視覚化

- **人**：千恵さん本人の表情と施術姿勢を、資格ロゴより強い信頼要素として扱う。
- **専門性**：肩甲骨・背中の写真を大きく見せ、一般的なフェイシャルサロンとの差を明確にする。
- **1対1**：広い店舗写真より、手元、カウンセリング、ベッド周りなど距離の近い写真を使う。
- **大人の美容**：ピンクを主張色にせず、深いローズと温かいアイボリーの面積差で品をつくる。
- **流れ・ほぐれ**：細い曲線、縦長写真、ゆるやかな余白の連続で表現する。人体図や医療的な図解は使わない。

# 2. デザイン原則

## 2.1 写真は装飾ではなく証拠として使う

千恵さん、施術、サロン、背面事例を主役にする。意味のない美容ストック写真や、実店舗と誤認される生成画像は使わない。

## 2.2 可読性の上にエレガンスを置く

明朝体は見出しと短い引用だけに限定し、本文・料金・ボタン・FAQは視認性の高いゴシック体にする。淡色の文字、細すぎる書体、画像内文字への依存を避ける。

## 2.3 セクションの役割ごとに構図を変える

Heroは写真、悩みはコピー、選ばれる理由は人と専門性、メニューは料金、事例は比較写真、CTAは行動に集中させる。同型カードを連続させない。

## 2.4 やさしさと明確さを両立する

輪郭は柔らかくしても、CTA、リンク、料金、見出しのコントラストは曖昧にしない。装飾より、サイズ・余白・位置によって優先順位を示す。

## 2.5 変化を誇張しない

Before/Afterは同寸・同条件に近い写真を並べ、色補正や切り抜きで差を強調しない。結果保証に見える演出、点滅、強い矢印、煽るバッジは使用しない。

# 4. タイポグラフィ

## 4.1 フォントファミリー

### 日本語・本文/UI

`Zen Kaku Gothic New`, `Hiragino Kaku Gothic ProN`, `Yu Gothic`, sans-serif

- 目的：親しみと可読性の両立。
- 使用箇所：本文、ナビゲーション、ボタン、料金、FAQ、店舗情報。
- 使用ウェイト：400 / 500 / 700。

### 日本語・ディスプレイ

`Shippori Mincho`, `Yu Mincho`, serif

- 目的：大人女性に合う静かな上質感。
- 使用箇所：H1、主要H2、短い引用。
- 使用ウェイト：500 / 600。
- 長文、料金、操作ラベルには使用しない。

### 英字アクセント

原則として`Shippori Mincho`, `Yu Mincho`, serifを英字にも共用し、基本構成を2ファミリーに抑える。

- 使用箇所：小さなセクションラベル、`Private salon cherish`の仮テキストロックアップ。
- italicは1〜3語の短い装飾に限定する。
- リファレンス画像で明確な効果が確認できた場合のみ、`Cormorant Garamond`の600を追加候補とする。

- `Zen Kaku Gothic New`：400 / 500 / 700

# 5. レイアウト・グリッド

## 5.1 コンテナ

```css
--container-max: 1200px;
--prose-max: 704px;
--narrow-max: 560px;
--page-gutter: clamp(20px, 4vw, 48px);
```

- 通常コンテンツ：最大1200px。
- 読み物：最大704px。
- FAQ・料金説明等の狭い本文：最大800px。
- Hero・最終CTA・写真主体セクションは全幅背景を許可し、内部要素だけコンテナへ揃える。

## 5.2 ブレークポイント

| Name | Range | Grid | Gutter |
|---|---|---|---|
| Mobile | `0–767px` | 4 columns | 16px |
| Tablet | `768–1023px` | 8 columns | 24px |
| Desktop | `1024–1279px` | 12 columns | 24px |
| Wide | `1280px+` | 12 columns | 32px |

レイアウトはコンテンツが窮屈になる地点で切り替え、機種名には依存しない。

## 5.3 左右余白

- 360〜389px：20px
- 390〜767px：24px
- 768〜1023px：32px
- 1024px以上：48px。ただしコンテナ最大幅で中央配置。

## 5.4 セクション余白

| Token | Mobile | Desktop | 用途 |
|---|---:|---:|---|
| `section-xs` | 48px | 72px | 補助セクション |
| `section-sm` | 64px | 96px | FAQ、アクセス |
| `section-md` | 88px | 136px | 標準セクション |
| `section-lg` | 112px | 176px | 写真・世界観セクション |
| `section-hero` | 96px + header | 120px + header | Hero |

全セクションを同じ余白にしない。写真主体は広く、情報整理はやや詰め、CTA前は大きく間を取る。

## 5.5 スペーシングスケール

`4, 8, 12, 16, 24, 32, 48, 64, 88, 112, 136, 176px`

原則8px系統。4pxと12pxはラベル等の小間隔に限定する。

## 5.6 角・影

- 写真大：`border-radius: 32px 32px 8px 32px`など一角だけ小さい非対称形。
- 写真小：16px。
- 情報面：16px。
- CTA：999pxのピル型は使わず、12px。行政UIにも美容アプリにも寄せない。
- 影：`0 16px 48px rgba(63, 35, 41, .10)`を写真の浮遊表現に限定。
- すべてをカード化せず、面・罫線・余白を優先する。

# 6. 写真・画像アートディレクション

## 6.1 写真の優先順位

1. 千恵さんの自然な表情、施術者としての姿
2. 肩甲骨はがしの施術中の手元・背面
3. 顔が写らないBefore/After
4. カウンセリングの手元・記入風景
5. サロン室内・施術ベッド・テクスチャ
6. 外観・入口・アクセス補助

## 6.2 撮影・選定トーン

- 自然光または拡散光。白飛びさせず、肌色を自然に保つ。
- 色温度はやや暖色。黄ばみ、ピンク被りは抑える。
- 彩度は原則`-5〜-10%`、コントラストは弱め、黒レベルは潰さない。
- シーツや制服の白は純白ではなくアイボリー寄りに統一する。
- 美肌補正、身体の輪郭修正、背景の過度なぼかしは禁止。

## 6.3 トリミング

| 用途 | Aspect ratio | object-position |
|---|---|---|
| Hero portrait | Desktop `4/5`、Mobile `4/5` | 顔 `50% 28%`を基準に個別調整 |
| 施術ワイド | `16/10` | 手元と肩甲骨が中央に残る位置 |
| Profile | `4/5` | 顔と手元が同時に見える位置 |
| Before/After | 各画像同一の`3/4`または元画像比 | 背骨中心を同じX位置に揃える |
| Interior | `16/9` | ベッド全景、余白側へ文字は置かない |
| Quote texture | `3/2` | シーツや手元を抽象的に見せる |

BeforeとAfterは別々に都合よく切り取らず、共通のフレームと拡大率を使う。

## 6.4 写真と文字の重ね方

- 本文は原則、写真へ直接重ねない。
- Heroで重ねる場合は、写真の空白域＋半透明ではない単色面を組み合わせる。
- 最終CTAのみ、写真上へ`rgba(63,35,41,.78)`程度の濃色オーバーレイを許可する。
- 可読性をドロップシャドウだけに依存しない。
- 画像内のInstagram文字は主要情報として扱わず、HTMLテキストで再構成する。

## 6.5 PC / Mobile

- PCでは写真をグリッドから1〜2カラム分はみ出させ、エディトリアルな非対称をつくる。
- Mobileでははみ出しを最大12px程度に抑え、横スクロールを発生させない。
- Mobileで被写体が小さくなる写真は、別トリミング用の`<picture>`を用意する。
- 重要写真の上に固定CTAが重ならないよう、下部safe areaを確保する。

## 6.6 Before/After固有ルール

- 自動カルーセルにしない。最低2事例は最初から閲覧できる。
- Desktopは左右比較、Mobileも2列比較を維持し、各画像幅が不足する場合は事例単位で縦積みする。
- ラベルは写真外または上端の単色ラベルに置き、`Before` / `After`を明記する。
- 「施術1回」「30代」等は写真上ではなく説明領域へ置く。
- 個人差注記は事例群の直下に14px以上で表示する。

## 6.7 画像アセット割り当て表

リファレンス画像作成時は、以下のIDで仮素材・本番素材を管理する。スクリーンショットしかない項目は低解像度のまま最終実装へ使用しない。

|---|---|---|---|---|
| `IMG-HERO-01` | Hero | 千恵さんの施術姿または自然なポートレート | 4:5 | 元画像未提供 |
| `IMG-TREAT-01` | 肩甲骨の説明 | 肩・背中への施術中の手元 | 16:10 | 元画像未提供 |

# 7. UIコンポーネント

## 7.1 Header

### Desktop

- 高さ：通常88px、スクロール後72px。
- 初期：`background: rgba(252,249,245,.88)`、`backdrop-filter: blur(16px)`。
- 左：仮テキストロックアップ `Private salon cherish`。
- 中央〜右：`施術について / 選ばれる理由 / 事例 / ご予約`。
- 最右：Primary CTA、幅176px、高さ52px。
- `position: sticky; top: 0; z-index: 50;`。

### Mobile

- 高さ64px。
- ロックアップ＋メニューボタン。CTAは下部固定バーへ分離。
- メニューボタンは48×48px、テキストの代替名を持つ。
- 展開メニューは画面右からの小さなドロワーではなく、読みやすい全幅パネル。背景スクロールをロックし、Escで閉じる。

### States

- hover：リンク下線が左から右へ表示。
- focus-visible：黄色2px＋濃色1pxの二重リング、offset 3px。
- active：該当セクションのリンクを太字＋下線。色だけで示さない。

## 7.2 Navigation

- アンカー移動時に固定ヘッダー分の`scroll-margin-top: 96px`を設定。
- スクロール連動のactive表示は任意。実装する場合も現在地を`aria-current="location"`で補足する。
- スムーススクロールは`prefers-reduced-motion`時に無効。

## 7.3 Button / CTA

### Primary

- 高さ：56px、Mobile固定CTAは58px。
- padding：`0 28px`。
- 背景：`cta-default`、文字：白、角12px。
- ラベル例：「LINEで相談・予約する」。LINEアイコンを付ける場合もラベルを省略しない。
- hover：`cta-hover`＋`translateY(-1px)`＋弱い影。
- active：`cta-active`＋移動なし。
- focus-visible：二重リング。
- disabled：サンプルLPでは作らない。リンク未設定時はボタン表示せず、静的な「提案用」注記にする。

### Secondary

- 高さ：56px。
- 白または透明背景、2px `primary-700`枠、文字`primary-700`。
- hover：`background-warm`。
- ラベル例：「Hot Pepperで空き状況を見る」。

### Button group

- Desktop：横並び、gap 16px。
- Mobile：縦積み、Primaryを先頭、幅100%、gap 12px。
- すべて44×44px以上の操作領域を確保する。

## 7.4 Card

カードは用途別の3種だけに限定する。

1. `EvidenceCard`：Before/After事例。写真が主、枠線のみ。
2. `PricePanel`：主役メニュー。濃色面または白面、料金を主役にする。
3. `InfoPanel`：営業時間等。影なし、罫線または背景差のみ。

「選ばれる理由」や「悩み」を同型カードで3〜6枚並べない。

## 7.5 Link

- 本文リンク：`link`色＋1px下線、underline-offset 4px。
- hover：下線2px、`primary-800`。
- visited：同系の`#704F6D`を使用可能。ただしナビ・CTAはvisited変化なし。
- 外部リンクは必要に応じ外部リンクアイコンとスクリーンリーダー用テキストを付ける。

## 7.6 FAQ

- `details` / `summary`を第一候補にする。
- 質問行：最小64px、padding `20px 0`、上下1px罫線。
- 右端：プラス／マイナス。アイコンは`aria-hidden="true"`とし、質問文を操作名にする。
- ネイティブ`details / summary`では、開閉状態をブラウザへ任せ、`aria-expanded`を手動で追加・同期しない。
- 独自の`button`型アコーディオンへ変更する場合のみ、`aria-expanded`と`aria-controls`を正しく同期する。
- hover：質問文を`primary-700`へ。
- focus-visible：行全体に二重リング。
- open：回答背景を変えず、左に2px `secondary-500`の罫線。回答padding `8px 24px 24px`。
- 料金・営業時間・予約方法など重要情報をFAQだけに隠さない。

## 7.7 Access

- 店舗情報は`dl`、営業時間等の表形式が必要なら`table`を使う。
- 地図は埋め込みより、静的な簡易地図画像＋「Google Mapsで開く」リンクを推奨。読み込み負荷と操作混乱を抑える。
- 住所はコピー可能なHTMLテキストにする。
- 駅からの徒歩情報はアイコンだけにせずテキストで表示。

## 7.8 Reservation / Contact

- 中盤のメニュー直後、アクセス前、最終CTAの計3箇所を基本とする。
- Mobile下部固定CTAはHero内では表示せず、Heroを通過した後に表示する。
- 最終CTA・Footerへ到達したら、重複とコンテンツ遮蔽を避けるため非表示にする。
- 表示制御はIntersection Observerを使用し、利用できない場合は常時表示ではなくセクション内CTAへフォールバックする。
- 固定バー：白背景、上border、`padding-bottom: max(10px, env(safe-area-inset-bottom))`。
- 電話番号は公開資料で確認できないため設けない。

## 7.9 Footer

- 背景`#2E2725`、文字`text-on-dark`。
- 仮ロックアップ、住所、Instagram、予約リンク、コピーライト。
- 法的ページが存在しないサンプルでは架空リンクを作らない。
- 高さを過度に大きくせず、Mobile固定CTA分の下余白を確保。

# 8. セクション別アートディレクション

## 8.1 Hero

### 目的

「誰向けの何のサロンか」「誰が対応するか」「次に何をすればよいか」を最初の画面で理解させる。

### Desktop

- `min-height: calc(100svh - var(--header-height))`を基本とし、固定の最小720pxは設けない。
- 通常の上下余白は`clamp(64px, 8vh, 112px)`。高さ760px以下のDesktopでは上下56pxへ縮小する。
- コンテンツが収まらない場合は高さを自動的に伸ばし、CTAを切り落とさない。
- 12カラム。コピー1〜6列、写真7〜12列。写真は右端までフルブリード。
- 左上に小さな`YOKOHAMA / PRIVATE SALON`、中央にH1、下に短い説明とCTA。
- 写真は千恵さんの施術姿または自然なポートレート。右側に人物、左側に余白のある構図。
- 背景は`background-base`。H1の一部に細いローズの下線を1箇所だけ使用。
- 装飾は大きな半透明円ではなく、写真背後の細い曲線1本とゴールドの小点のみ。

### Mobile

- 順序：Overline → H1 → 補助コピー → 写真 → Primary CTA → Secondary link。
- H1は3〜4行以内、38〜44px。
- 写真は画面幅いっぱいではなく左右20px、4:5。人物の顔と手元を残す。
- CTAは本文内＋固定バー。Hero内CTAの直下に「メニューが決まっていなくても相談できます」。

### 前後との変化

Heroは写真と明朝の静けさ。次の悩みセクションは写真を減らし、大きなゴシックコピーでテンポを変える。

## 8.2 共感・悩み提示

### 目的

利用者が自分の悩みとして認識し、スクロールを続ける理由をつくる。

### Desktop

- 背景`background-warm`、section padding `section-lg`。
- 左3〜5列に大きな導入コピー、右7〜12列に悩みを縦に並べる。
- 悩み項目はカード化せず、1項目ごとに薄い罫線＋48px以上の余白。
- 右端に小さく背中のクローズアップ写真を1枚だけ縦長配置してもよい。

### Mobile

- 導入コピーの後、悩みを1列で表示。
- 各項目は24px前後の太字。チェックアイコンは使わず、01〜05の小さな番号を添える。
- 写真はセクション最後に横長で置き、次セクションへの橋渡しにする。

### 視覚的主役

「後ろ姿が以前と違って見える」「肩まわりが厚く見える」等の共感コピー。

## 8.3 肩甲骨と後ろ姿に着目する理由

### 目的

サービスの考え方を理解させる。ただし医学的な因果・治療効果は説明しない。

### Desktop

- 白背景。
- 12カラムの非対称。施術の手元写真を1〜7列、テキストを8〜12列。
- 写真の下端をテキストより64px下へ伸ばし、前セクションと違う縦の動きをつくる。
- 3つの説明は見出し＋2行程度。図解カードにはしない。

### Mobile

- 写真 → H2 → 3つの説明。
- 説明は左罫線で束ねる。写真と文章のDOM順も同じにし、CSSで無理に順序を変えない。

### コピー上の制約

「本来の位置に戻す」「巡りが動き出す」「根本原因」等は使わない。「肩・背中まわりを丁寧にケアする」「後ろ姿を確認しながら施術する」とする。

## 8.4 cherishが選ばれる理由

### 目的

競合との違いを、人、専門性、環境の3軸で伝える。

### Desktop

- 1つの大きな千恵さん写真を左1〜5列に固定的に見せ、右7〜12列へ番号付き理由を縦配置。

- 資格はバッジ化せず、文章として控えめに表示。

### Mobile

- H2 → 写真 → 理由リスト。

### 前後との変化

ページ中盤で唯一の濃色セクション。次の料金セクションはアイボリーへ戻し、視界を開く。

## 8.5 主役メニュー・料金

### 目的

「何を、いくらで、どのくらい受けるか」を迷わず理解させ、予約行動へつなげる。

### Mobile

### CTA

Primary / Secondaryを両方設置する最初の主要地点。

## 8.6 背面Before/After

### 目的

施術の見え方を、誇張せず具体的に示す。

### Desktop

# 9. モーション

モーションは「落ち着き」「丁寧さ」を補助する範囲に限定する。

## 9.1 Scroll Reveal

- 対象：H2、写真、理由リスト、料金パネル。
- CSSの通常状態ではすべて表示し、JavaScriptが利用できない場合も内容を失わない。
- JavaScript初期化後にルートへ`.js`を付与した場合のみ、未表示要素を`opacity: 0; transform: translateY(16px);`にする。
- 完了：`opacity: 1; transform: none;`
- duration：480ms。
- easing：`cubic-bezier(.22, 1, .36, 1)`。
- stagger：最大80ms。文章を1文字ずつ出さない。
- 一度表示したら再実行しない。
- Intersection Observerが利用できない場合はRevealを実行せず、全要素を表示する。

```css
[data-reveal] {
  opacity: 1;
  transform: none;
}

.js [data-reveal]:not(.is-visible) {
  opacity: 0;
  transform: translateY(16px);
}
```

## 9.2 Hover

- Button：160ms、色＋1pxの浮上。
- Text link：下線太さまたは位置の変化、160ms。
- 写真：原則ズームしない。クリック可能なギャラリーがある場合のみ`scale(1.015)`。

## 9.3 Header / Menu

- Header縮小：240ms。大きなジャンプを起こさない。
- Mobile menu：opacity＋8px移動、240ms。
- 背景スクロールロック、フォーカストラップ、閉じた後のフォーカス復帰を実装。

## 9.4 Reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  html {
    scroll-behavior: auto;
  }

  [data-reveal],
  .mobile-menu,
  .site-header {
    animation: none !important;
    transition: none !important;
    opacity: 1 !important;
    transform: none !important;
  }
}
```

パララックス、自動カルーセル、背景動画、連続ループアニメーションは使用しない。

# 10. レスポンシブ方針

## 10.1 Mobileを独立した構成として設計する

- Desktopの2カラムを機械的に縦積みせず、理解順に並び替える。
- ただしDOM順と視覚順を大きくずらさず、スクリーンリーダーの読み上げ順を保つ。
- Heroはコピーを先に、Profileは写真前後の文脈を優先、Menuは料金を写真直後に置く。
- Mobileの装飾曲線、はみ出し、影は半減する。
- セクション見出しの強制改行はMobile専用に再設計する。

## 10.2 画像

- `next/image`の`fill`使用時は親へ明示的なaspect-ratioを設定する。
- `sizes`例：Hero `'(max-width: 767px) 100vw, 50vw'`。
- PCとMobileで焦点が変わる場合は`<picture>`または別`object-position`を用いる。
- スクリーンショットをそのまま背景画像として使用しない。

## 10.3 CTA

- MobileではHero通過後に下部固定CTAを表示し、Primary 1つに絞る。
- Secondaryは各主要セクション内に置く。
- 固定CTAにより本文が隠れないよう、`body`末尾にsafe areaを含む余白を追加する。
- 最終CTAとFooterでは固定CTAを非表示にする。表示・非表示によるレイアウトシフトは発生させない。

## 10.4 情報量

- 長いプロフィールや全メニューは省略し、外部リンクへ送る。
- 重要な料金・時間・場所・予約方法は省略しない。
- FAQは折りたためるが、質問文だけで内容を予測できるラベルにする。

## 10.5 最小幅

- 320pxでも機能を失わない。
- 基準確認幅：320 / 360 / 390 / 768 / 1024 / 1280 / 1440px。
- 横スクロール検証はブラウザの200%拡大でも行う。

# 11. アクセシビリティ・実装ルール

## 11.1 HTML構造

- `header`, `nav`, `main`, `section`, `footer`を適切に使用する。
- H1は1つ。H2→H3の順を飛ばさない。
- セクションには`aria-labelledby`で見出しを関連付ける。
- 店舗情報は`address`、用語と値は`dl`、手順は`ol`を使う。
- ページ遷移は`a`、開閉操作は`button`または`summary`。見た目で要素を取り違えない。

## 11.2 コントラスト

- 原則、文字はサイズに関係なく背景と4.5:1以上を目標とする。
- UI境界、アイコン、フォーカス表示は隣接色と3:1以上。
- 写真上文字はオーバーレイ込みで実測する。
- 淡いローズ、ゴールド、ベージュを本文色にしない。

## 11.3 Focus / Keyboard

- すべてのリンク、ボタン、summary、メニューボタンへ`focus-visible`を表示。
- focus ring：内側2px `focus-inner`、外側1px `focus-outer`、offset 3px。
- ヘッダーにスキップリンク「本文へ移動」を設置。
- Mobile menuはEscで閉じ、閉じた後にトリガーへフォーカスを戻す。
- FAQはEnter/Spaceで操作できる。

## 11.4 操作領域

- すべての主要操作は44×44px以上。
- 隣接リンク間は最低8px、Mobileナビでは12px以上。
- アイコンのみの操作には視覚ラベルまたはアクセシブルネームを付ける。

## 11.5 画像・代替テキスト

- 千恵さんの写真：役割・状況が分かる簡潔なalt。
- 施術写真：施術部位と行為を簡潔に説明。
- Before/After：視覚的な断定をaltへ書かず、「30代・施術1回の背面比較」等の事実を記載。詳細説明は本文へ。
- 装飾写真：`alt=""`。
- 画像内文字がある場合、同等内容を本文にも置く。

## 11.6 拡大・リフロー

- 固定px幅で本文を閉じ込めない。
- 200%文字拡大で重なり・切れ・操作不能が起きない。
- `height`固定はHero等の装飾領域に限定し、本文コンテナでは`min-height`を用いる。
- CSS Gridの`order`で意味順を変更しない。

## 11.7 Next.js / React実装指針

- App Routerを前提にしても、必須機能はクライアントJSへ依存させない。
- FAQは可能ならネイティブ`details`で実装。
- `next/font/google`で必要ウェイトのみ読み込み、`display: swap`相当を使用。
- `next/image`で画像最適化。LCP対象のHeroのみpriority相当、他は遅延読み込み。
- アンカーID、CTA URL、店舗情報、料金、事例はデータオブジェクトへ分離し、公開前差し替えを容易にする。
- `prefers-reduced-motion`、`prefers-contrast`を妨げない。
- Lighthouseだけでなく、キーボード、VoiceOver、200%拡大、低速回線を手動確認する。

## 11.8 パフォーマンス目標

営業提案用サンプルでも、実公開へ移行できる水準を目標とする。

- LCP：2.5秒以内を目標
- CLS：0.1未満
- INP：200ms以内を目標
- Hero画像：AVIFまたはWebP、表示寸法に応じた`srcset`を生成
- Hero以外の画像：原則遅延読み込み
- 初回表示で読み込むWebフォント：日本語2ファミリー、合計5ウェイト以内
- 不要なクライアントコンポーネント、アニメーションライブラリ、アイコンライブラリを導入しない
- Scroll RevealはIntersection ObserverとCSSで実装し、専用ライブラリを追加しない

数値は実回線・実端末で確認し、Lighthouseの単一スコアだけを合否基準にしない。

## 11.9 対応ブラウザ

- 最新2世代のChrome、Safari、Edge、Firefox
- iOS SafariおよびAndroid Chromeの現行主要バージョン
- JavaScriptが失敗した場合でも、本文、料金、店舗情報、予約リンクを閲覧できる
- `backdrop-filter`、`@container`等が非対応でも、単色背景・通常メディアクエリへ自然にフォールバックする
- Internet Explorerは対象外

# 12. NGデザイン

## 12.1 行政サイト化

- 青系キーカラー、白背景、均等カード、太い罫線だけで構成しない。
- デジタル庁のコンポーネント外観、アイコン、角形状、レイアウトをそのまま複製しない。
- 「正しいが無表情」な情報ページにせず、写真とエディトリアルな余白で店舗の人柄を示す。

## 12.2 単調なLP

- 全セクションを白背景＋中央見出し＋3カードにしない。
- すべてを同じ幅、同じ角丸、同じ影で囲まない。
- 左右交互配置だけを機械的に繰り返さない。
- 写真、コピー、情報整理、濃色面、CTAでページの速度を変える。

## 12.3 美容テンプレート化

- ピンク、金、筆記体、花、キラキラを大量に使わない。
- 細すぎる明朝体や英字筆記体を本文へ使わない。
- 女性の顔や肌のストック写真で埋めない。
- 千恵さん本人よりモデルを大きく扱わない。

## 12.4 煽り・誇張

- 点滅、赤い強調、カウントダウン、限定感の捏造をしない。
- 「1回で別人級」「若返る」「10kg減」「根本改善」等を掲載しない。
- Before/AfterのAfterだけ明るくする、細く切り取る、姿勢差を隠す等をしない。
- 医療監修のような白衣・十字・人体解剖図を装飾に使わない。

## 12.5 操作性を損なう表現

- 自動カルーセル、横スワイプ必須の事例、過剰なパララックスを使わない。
- 薄い文字、画像内だけの情報、アイコンだけのCTAを使わない。
- hoverでしか分からない情報を作らない。
- 固定CTAで本文やFooterを隠さない。

# 13. 最も重要なデザイン上の判断

1. **主役は装飾ではなく「千恵さん本人」と「背中の実例」**  
   個人サロンの信頼をつくるため、Hero・選ばれる理由・プロフィールで施術者の存在を一貫して見せる。顧客の顔写真は使用しない。

2. **くすみピンクを面積ではなく温度として使う**  
   ベースはアイボリー、締めは深いボルドー、ローズは補助に限定し、40〜60代が「かわいい」より「品がよく安心」と感じる配色にする。

3. **セクションごとに視覚的な役割を変える**  
   Hero＝写真、悩み＝コピー、理由＝人と専門性、メニュー＝価格、事例＝比較、声＝感情、FAQ＝情報整理、最終CTA＝行動、と明確に切り替える。

4. **アクセシビリティをブランド表現の制約ではなく品質の土台にする**  
   16px以上の本文、十分な行間、44px以上の操作領域、明確なfocus、4.5:1以上の文字コントラストを守り、その上で明朝・余白・写真構図による独自性をつくる。

5. **Before/Afterを強く見せても、強く言い切らない**  
   比較条件と注記を明示し、加工や煽りコピーを避ける。結果保証ではなく、相談判断に必要な具体的情報として提示する。
